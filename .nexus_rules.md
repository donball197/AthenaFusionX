# NEXUS Workspace Rules — v2026.05.05 [ANTI-LOOP + GROUNDING]

## Core Principles
- Minimal surgical changes only.
- Preserve style, formatting, and comments.
- After any edit, run `cargo check`.
- Relative paths only.

## ABSOLUTE OUTPUT RULES
- **ONLY** a valid JSON array of AgentActions.
- No text outside the array. No thinking. No markdown.
- Response must start with `[` and end with `]`.
- `"reasoning"` ≤ 12 words.

## ONE ACTION PER TURN (MANDATORY)
- Exactly **one** action per response.
- After `read_file`, `diff_patch`, `write_file`, `execute_command`, or `patch_function` — **stop immediately**.
- Do **not** repeat the same `read_file` on a file you just read unless the previous action failed with `PATTERN_NOT_FOUND`.

## EDITING WORKFLOW (STRICT ORDER)
1. `read_file` — only when you need fresh content.
2. `diff_patch` — **preferred** for surgical edits. Use **exact** string from the most recent `[READ_OK]` block.
3. `patch_function` — only if explicitly requested for AST changes.
4. `write_file` — for large changes only.
5. `execute_command "cargo check"` — to verify.
6. `halt` — **only** when goal is achieved and verified.

## DIFF_PATCH RULES (CRITICAL)
- Copy `search` **exactly** from the latest `[READ_OK]` content (including whitespace where relevant).
- Keep `search` short but unique.
- After `[DIFF_PATCH_OK]`, do **not** patch the same thing again.
- If the desired change is already present, output `halt` immediately.
- Never reuse a search that caused `PATTERN_NOT_FOUND`.

  "type": "diff_patch",
  "path": "src/main.rs",
  "search": "IGNITION SEQUENCE INITIATED (v3.9.0)",
  "replace": "IGNITION SEQUENCE INITIATED (v4.0.0)",
  "reasoning": "Update version to v4.0.0"
}
