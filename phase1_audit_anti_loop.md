# Anti-Loop Subsystem Audit Report: Relevance Scoring & Duplicate Classification Logic (Phase 1 Recon)  ## Relevance Scoring (`score_search_relevance`)  - **Purpose**: Assigns a 0.10–0.95 relevance score to search evidence against a query.  - **Hard-coded penalties**:  - 0.10 for failed actions (`[action failed]`, `[search_code_error]`, `os rejected action`).  - 0.40 for empty-result markers (`no code matches found`, `no matches found`, `0 results`).  - 0.45 if the evidence body is empty after stripping protocol lines.  - **Core scoring**:  - Tokenizes the query on non-alphanumeric/underscore boundaries, keeps terms ≥ 2 chars.  - Computes `overlap_ratio` = fraction of query terms present in evidence (case-insensitive).  - Adds a `density_bonus` up to 0.15 for up to 6 non-empty body lines.  - Final formula: `(0.55 + 0.25 * overlap_ratio + density_bonus).clamp(0.45, 0.95)`.  - **Belief gate** (`should_raise_belief`): Returns true if `score >= threshold` **or** `score >= 0.30` (hard floor).  ## Duplicate Classification (`classify_duplicate`)  - **Three-way outcome enum** (`FilterOutcome`):  - `FilterAndDecay` — stale duplicate, suppress and decay.  - `ConditionSatisfied` — duplicate command already executed and verified in evidence; treat as satisfaction, no decay.  - `AllowRetry` — duplicate but contract still needs it and evidence shows prior failure; permit retry.  - **Decision logic** (in order):  1. **ExecuteCommand**: If the command hash matches a `CommandExecutionVerified` condition, return `ConditionSatisfied` when `command_condition_met` is true, else `AllowRetry`.  2. **WriteFile**: If the path is a required artifact and `has_artifact_write` is absent in evidence, return `AllowRetry` (earlier write failed).  3. **ReadFile re-read-after-write exemption**: If a `[WRITE_OK]` for the path appears after the last `[READ_OK]`, return `AllowRetry` (content changed).  4. **CortexFix whole-file read saturation**: If `OutcomeVerifier::mission_completion_authorized` confirms the path was already fully read, return `FilterAndDecay`.  5. **Read-like actions** (`ReadFileChunk`, `SearchCode`, `ReadFile`, `ReadFunction`): default to `AllowRetry`.  6. **All other actions**: `FilterAndDecay`.  ## Halt Fingerprinting  - `halt_reasoning_fingerprint`: Hashes `halt` + reasoning string via `DefaultHasher` to produce a u64 fingerprint.  - `halt_action_key`: Returns `halt:<hex_fingerprint>` for anti-loop key storage, ensuring revised halt bodies are not treated as duplicates.  ## Test Coverage  - Unit tests validate high-overlap scoring, re-read-after-write exemption, and suppression of failed/empty searches.  ---  *Source: `crates/runtime_core/src/anti_loop.rs` (full file read).*
